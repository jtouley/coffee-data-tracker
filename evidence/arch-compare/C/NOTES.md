# Design C: per-connector jobs + daily Shopify shards + retry sweep + HTML stub + weekly merge, ELT (C/wt: main 6bda240 + PR #62 + PAGINATION v2 of 18:24)
**Design.** `config/connectors.toml` declares each job's schedule and each connector's rate budget. `pipelines.py` runs every fetch job through ingest.run with extract-and-load only (`enrich_rules=False`), keeping per-store backoff, deferred rounds, and v2's resumable pages with 60/120/240 s backoffs and parking. A `RawSink` stands in for the Lake: rows land in `raw/connector=<c>/run_date=<d>/shard=<s>/data.parquet` (checkpoint parts of 25, compacted to one file; a re-run skips what's there). Shopify: sha256(id) mod 7 = weekday, ~153 stores/day at 1.5 req/s. Every job appends a per-store control manifest (ok / error / parked + retry_at / refused). The daily sweep reads it and retries parked stores in waves (+0/15/60/120 min) after their Retry-After, resuming from the blocked page. A store refused in 2 jobs >=1 h apart is routed to the `html_crawl` stub. Sun 21:00, merge: the latest ok fetch per roaster within 7 days (else the latest error) becomes one run_manifests/fetches/snapshots/bodies file in today's shape; the manifests roll up. 22:00, enrichment: rules for every coffee that landed without them, then Claude's candidates (`enrich.pending`: rules rows that need_llm, joined to bodies), collected and submitted. It runs weekly because data reaches the lake only at the merge, and one batch a week is what the build needs. 23:00 build+gate (`coffeedata build`), Mon 00:00 publish. Roaster status comes from the loaded snapshots (dim_roaster.sql and registry.STATE_SQL), not fetches.coffees.

**Principles.** Single-purpose services: connector/shard jobs, sweep, HTML hook, enrichment, merge, build+gate, publish, one CLI step each. DRY: everything goes through ingest.run, rows_for, rules_row, manifest_rows, enrich.pending/run and Lake. New connector: an adapter + a toml block, plus today's platform mapping (models.py +2, discover +1, dbt run_completeness +1), which is not yet config-only. Control plane: jobs never call each other; the sweep and the HTML hook read control/, the merge reads raw/, enrichment reads the lake; Cloud Scheduler does the timing.
**Contracts.** raw/v1: `pipelines.RAW` + `RAW_KINDS`, version in the Parquet metadata. control/v1: `pipelines.CONTROL` + `OUTCOMES`. enrichment: `lake.SCHEMAS['enrichments']` + `ingest.rules_row`. These three are pinned by tests/test_pipeline_contracts.py. public: contracts/public-catalog.odcs.yaml, checked by tests/test_contracts.py.
**Weaknesses.** 11 schedule entries. The control files are read-modify-write with no lock. Up to 7 days stale per store under one run_date. Refusal is read from error labels. Raw rows are untyped JSON. No internal deadline in ingest.run. is_coffee is still decided at load. The HTML crawler is unbuilt. The S2 headroom needs Shopify jobs never to overlap.
**Real condensed week (C/real.md).** All 1,070 Shopify roasters: 7 shards of 11.5-13.0 min at 1.5 req/s, then a 128-min sweep that recovered 16 of 57 parked. 1,027 ok = 96.0% [94.6, 97.0], 27 refused (routed to the stub), 13 parked, 0 430s, every job inside 240 min. 6 of A's 11 page-2 stores now succeed. The first-contact 429 rate fell from 16-27% to 4.5% on the last two shards (after 32-min gaps). The sweep's retries tripped the burst detector 7 times; that is fixed since (quiet_hosts).
**Cloud mapping.** One Cloud Run Job per step (same image: `coffeedata pipeline connector --connector X` / `sweep` / `html` / `merge` / `enrich`, `coffeedata build`, `coffeedata publish`) with one Cloud Scheduler cron each, 11 in all. Task timeout 240 min, maxRetries=1 (the day-5 resume). raw/, control/ and parked/ live in GCS (COFFEEDATA_RAW), with generation preconditions on control writes. Prefect Cloud later: the same 11 as cron deployments on a Cloud Run push pool, with a concurrency limit of 1 on a "shopify-ip" tag.
