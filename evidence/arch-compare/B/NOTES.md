# Design B: one weekly job per connector, a weekly merge, then enrich, build and publish (B/wt off origin/main 6bda240 + PR #62 + PAGINATION v1/v2; local, nothing pushed)
**Design.** `crawl --connector X` extracts and loads only (ELT): snapshots, bodies and fetches go into `raw/connector=X/run_date=<Mon>/`, one file per table after compaction, with its own deadline and resume. Shopify gets PR #62 plus page backoffs of 60/120/240 s with no worker held, parking after 3, `crawl-retry` for parked stores, 401/403/430 recorded as blocked, and a short page ending the catalog only once it reaches the store's last known size. `merge` (Sun 06:00) unions the partitions that the control table says landed into one file per table under the week's run_date: the same raw-run shape. `enrich-week --submit` (07:00) picks Claude's candidates from raw using the build's own rules. Build, gate and publish follow at 09:00.
**Sim** (localhost mocks, 10x clock; S1 = per-store limits, S2 = S1 + a 2 req/s IP-wide limit). All 13 jobs fit in 240 min (longest: 24 min S1, 44 min S2). Woo's outage slot got 0% ok and its resume slot 97.4%. The day-5 kill kept 200 of 349 roasters, and the resume finished. End of week: S1 96.4% ok (Shopify 93.2%, 66 refusers); S2 93.7% (Shopify 86.7%).
**dbt.** On fixture JSON, main's ingest and B's crawl + merge give identical marts/public tables (`sim/dbt_equiv.py`, 17 tables). Roaster status now comes from the build (dim_roaster + `registry.STATE_SQL`, both via `coffeedata/products.py`); the test that Python and dbt agree passes. dbt: +24/-21 (status only); app and contracts/: 0.
**Real Shopify job** (1,070 stores, B/real.md): 44 min, 4,101 requests, 816 429s, 0 430s, 96.3% ok. 4 of the 11 page-2 stores and 8 of A's 22 refused stores now succeed (targeted retest: 4/11 and 11/22).
**Code (src vs 6bda240):** +1,196/-109 (PR #62 +180/-13, pagination +257/-19, B ≈ +759/-77), plus 489 lines of generated contract JSON. 682 tests pass.
**Owner's principles, as B meets them:**
1. Single-purpose services: crawl / crawl-retry per connector, merge, enrich-week, build+gate, publish. They share one image and are separate jobs.
2. DRY shared modules: http, lake (SCHEMAS), the adapter interface, ingest.run, control.py (manifests), and products.py (one coffee decision for dbt, enrichment and registry).
3. A new connector = adapter + config: `adapters/<name>.py`, an ADAPTERS entry, models' platform mapping, and one `Connector(...)` line. Its rate limit comes from config; merge, enrich and build don't change.
4. Contracts, versioned and tested (generated from lake.SCHEMAS; a column change fails `tests/test_raw_contracts.py` until the version is bumped): raw = `src/coffeedata/contracts/raw.contract.json` (snapshots, bodies, fetches, parked/*.json); manifest/control = `manifest.contract.json` (run_manifests, job_manifests); enrichment = `enrichment.contract.json`; public = the unchanged ODCS/ODPS with `contracts/test_contracts.py`.
5. Control plane: the `job_manifests` table (job, connector, shard, run, status, counts, egress IPs, per-IP refusals, code version). Jobs write a row at start and at end; merge reads who landed, enrich reads that the merge ran, and `egress-check` flags an IP with over 8% first-contact refusals two runs in a row. Timing is Cloud Scheduler.
**Cloud Run Jobs + Scheduler.** One image and 4 job definitions (crawl with `--connector` overridden per execution, merge, enrich, build). 13 Scheduler entries. raw/ and parked/ live in GCS, so compaction is a rewrite and the merge publishes 4 files to HF in one commit.
**Weaknesses.**
- S2 got worse with v2: backed-off "quiet hosts" never trip the platform pause, so the first Shopify job parked 433 stores. They should still count when many distinct stores block together.
- Refused stores cost 7 min of backoff per job, and the short-page saving needs a store's history (it saved nothing on a fresh lake).
- A kill loses up to 200 roasters of work, the 5 connectors' fetches are spread over 5 days under one run_date, and there are 13 schedule entries.
- A sim enrich run (before the --submit guard) sent 2 real Claude batches; the owner let them run.
